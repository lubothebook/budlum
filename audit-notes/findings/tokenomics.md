# Tokenomics Module Findings

Files reviewed: src/tokenomics/mod.rs, reward_pool.rs, src/chain/fee_market.rs, src/chain/genesis.rs

## F-0030: Total supply conservation is enforced

- **Location**: `src/tokenomics/mod.rs` (842 lines)
- **What is wrong**: Not a finding. The tokenomics module enforces G-3 (no new minting path). The `minting_paths_are_counted` gate verifies this at CI time. The total supply of 100,000,000 BUD is split as: community 10%, liquidity 10%, ecosystem 20%, team 20%, burn reserve 40%.
- **Status**: closed (informational, positive assessment)

- **Status**: closed (informational, positive assessment)

## F-0032: Genesis allocations are empty in testnet template

- **Location**: `config/testnet-genesis.json:4`
- **What is wrong**: The testnet genesis template has empty allocations and empty validators arrays. The ceremony_status is "template_ready" and the ceremony_note explains this is a template.
- **Why it is wrong**: A node started with this template would refuse to produce blocks (no validators, no allocations). This is intentional: the real genesis is generated by `cargo run --manifest-path xtask/tools/Cargo.toml -- testnet-genesis` from operator records.
- **What it causes**: An operator who uses the template directly would get a non-functional chain. The code correctly refuses such a genesis.
- **How to fix it**: Not a bug. The testnet ceremony process generates the real genesis. Consider adding a note in TESTNET_FIRST_RUN.md.
- **Status**: open (informational)
