# Live status

The live state of every finding in the directive's single finding ledger
(section 14). Section 14.1 item 4 makes this file the output of live
verification, and milestone M0 makes it the first deliverable of the queue.

The table is generated by `ops/scripts/live_audit.py` from
`config/audit/ledger.json` and the working tree. Regenerate with `--write`,
verify with `--check`. The directive itself is not in the tree (section 0.1 item
5), so the identifiers of its tables live in that JSON file, in English.

## What the columns mean, and what they do not

* **Closing package** is the package the directive says closes the finding, and
  its state in brackets is the state `docs/work/PACKAGES.md` measures.
* **Recorded location** is the file the finding was recorded against. The
  directive records one for the findings of sections 14.4, 14.5 and 14.6, and
  none for the finding ledger of section 14.3.
* **Live state** is `unverified` unless a reproduction test exists. Section
  14.1 item 5 makes that test step one of a closure: the test is written first,
  it is red before the fix, and the PR carries the red output. No such test is
  in this tree for any of these rows, so no row claims `closed`.

The number that matters for the launch gate is the count of Critical and High
rows whose state is not `closed`, and it is in the summary at the top of the
generated block.
