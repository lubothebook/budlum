# Work packages

One row per work package of the directive (section 15.7, with the lock paths and
the test names of the section 15.8 card). The identifiers are the directive's
`IP-NN`; the repository and GitHub write `WP-NN` because the tree is English
(section 15.3 item 1).

The table is generated. Section 0.5 item 1 says a number that was not measured
does not go into a document, so the three measured columns come from
`ops/scripts/live_audit.py` and nothing here is typed by hand. Run

    python3 ops/scripts/live_audit.py --write

to regenerate the block between the markers, and

    python3 ops/scripts/live_audit.py --check

to fail when the committed block and the tree disagree. The `audit-ledgers` gate
in `xtask/gates` checks the same file structurally from CI.

## What no row says

No row says a package is done. Section 15.5 item 10 asks for the last commit
SHA, the CI run number and one piece of evidence per acceptance item, and this
tree has no merged package: every open pull request is unmerged, so there is no
commit on `main` to cite. `delivered, evidence pending` means the lock paths and
the card tests are both present, which is the strongest statement a working tree
can support on its own.
